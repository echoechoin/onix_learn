# 任务状态段

```c
typedef struct tss_t
{
    u32 backlink; // 前一个任务的链接，保存了前一个任状态段的段选择子
    u32 esp0;     // ring0 的栈顶地址
    u32 ss0;      // ring0 的栈段选择子
    u32 esp1;     // ring1 的栈顶地址
    u32 ss1;      // ring1 的栈段选择子
    u32 esp2;     // ring2 的栈顶地址
    u32 ss2;      // ring2 的栈段选择子
    u32 cr3;
    u32 eip;
    u32 flags;
    u32 eax;
    u32 ecx;
    u32 edx;
    u32 ebx;
    u32 esp;
    u32 ebp;
    u32 esi;
    u32 edi;
    u32 es;
    u32 cs;
    u32 ss;
    u32 ds;
    u32 fs;
    u32 gs;
    u32 ldtr;          // 局部描述符选择子
    u16 trace : 1;     // 如果置位，任务切换时将引发一个调试异常
    u16 reversed : 15; // 保留不用
    u16 iobase;        // I/O 位图基地址，16 位从 TSS 到 IO 权限位图的偏移

} _packed tss_t;
```

## 切换原理（from ai）

在 x86 架构中，任务状态段（Task State Segment, TSS）可以支持硬件任务切换，但正如前文所述，现代 Linux 并不使用硬件任务切换，而是通过软件方式实现上下文切换。不过，为了回答你的问题，我会详细讲解 TSS 在 x86 架构中如何实现硬件任务切换的流程，以及 Linux 中与 TSS 相关的上下文切换机制。

### TSS 实现硬件任务切换的流程

在 x86 架构中，TSS 配合全局描述符表（GDT）和任务寄存器（TR）支持硬件任务切换。以下是硬件任务切换的详细流程：

1. **TSS 结构准备**：
   - 每个任务都有一个对应的 TSS 结构，存储在内存中，包含任务的完整上下文（如寄存器、堆栈指针、CR3 等）。
   - TSS 通过 GDT 中的 TSS 描述符索引，描述符包含 TSS 的基地址和大小。
   - 任务寄存器（TR）保存当前任务的 TSS 描述符选择子。

2. **触发任务切换**：
   任务切换可以通过以下方式触发：
   - **JMP 或 CALL 指令**：直接跳转或调用 TSS 描述符（GDT 中的任务选择子）。
   - **中断或异常**：通过中断描述符表（IDT）中的任务门（Task Gate）触发。
   - **IRET 指令**：从中断返回时，若目标任务的 TSS 选择子被指定，会触发任务切换。

3. **硬件任务切换的步骤**：
   当 CPU 检测到需要切换任务（例如通过 JMP 或 CALL 到 TSS 描述符），硬件会自动执行以下步骤：
   - **保存当前任务状态**：
     - CPU 将当前任务的上下文（所有寄存器，包括 EFLAGS、EIP、段寄存器、堆栈指针等）保存到当前 TSS 中。
     - 当前 TSS 的地址由 TR 寄存器指定。
   - **加载新任务的 TSS**：
     - CPU 从 GDT 中读取目标任务的 TSS 描述符，获取新 TSS 的地址。
     - 更新 TR 寄存器，使其指向新任务的 TSS 选择子。
   - **恢复新任务状态**：
     - CPU 从新 TSS 中加载目标任务的上下文，包括：
       - 通用寄存器（EAX、EBX 等）。
       - 段寄存器（CS、DS、SS 等）。
       - 堆栈指针（ESP、SS）。
       - 控制寄存器 CR3（切换页面表）。
       - 指令指针（EIP，恢复执行位置）。
   - **设置任务忙标志**：
     - GDT 中新任务的 TSS 描述符的忙标志（Busy Bit）被置为 1，表示该任务正在运行。
     - 原任务的 TSS 描述符忙标志被清除。
   - **开始执行新任务**：
     - CPU 根据新任务的 EIP 和 CS 继续执行。

4. **中断和堆栈切换**：
   - 如果任务切换涉及特权级变化（例如从用户态到内核态），CPU 使用 TSS 中指定的特权级堆栈（SS0、ESP0 等）来切换堆栈。
   - 在 x86-64 中，TSS 还支持中断堆栈表（IST），用于在中断处理时切换到独立的堆栈。

5. **返回原任务**：
   - 如果使用 CALL 指令触发任务切换，CPU 会记录返回信息（原任务的 TSS 选择子）。
   - 使用 IRET 指令可以返回到原任务，重复上述保存和加载过程。

### Linux 中与 TSS 相关的上下文切换流程

虽然 Linux 不使用 x86 的硬件任务切换，但 TSS 仍然在某些场景下（例如特权级切换）发挥作用。以下是 Linux 中上下文切换的流程，以及 TSS 的具体角色：

1. **上下文切换的触发**：
   - Linux 的上下文切换通常由内核调度器触发，例如：
     - 进程时间片用尽（调度器调用）。
     - 系统调用或中断导致进程阻塞。
     - 更高优先级的进程被唤醒。
   - 调度器调用 `schedule()` 函数，选择下一个运行的进程。

2. **保存当前进程上下文**：
   - 内核通过 `switch_to` 宏（定义在 `arch/x86/include/asm/switch_to.h`）保存当前进程的上下文。
   - 保存的内容包括：
     - 通用寄存器（通过 `push` 指令或直接存储到进程的 `task_struct`）。
     - 栈指针（ESP）。
     - 指令指针（EIP，保存调用点）。
     - 页面表基址（CR3，若需要切换地址空间）。
   - 这些信息存储在进程的 `task_struct` 数据结构中，而非 TSS。

3. **TSS 的作用**：
   - Linux 为每个 CPU 核心维护一个 TSS，存储在内核内存中，通过 GDT 的 TR 寄存器引用。
   - TSS 主要用于：
     - **特权级切换时的堆栈管理**：
       - 当从用户态（特权级 3）切换到内核态（特权级 0，例如系统调用或中断），CPU 从 TSS 的 SS0 和 ESP0 字段加载内核堆栈。
       - 在 x86-64 中，TSS 的 IST 机制可能用于中断处理时的堆栈切换。
     - **I/O 权限控制**：
       - TSS 中的 I/O 权限位图决定用户态进程是否可以直接访问 I/O 端口（通过 `in` 和 `out` 指令）。
   - Linux 不使用 TSS 保存完整的任务上下文，只用于堆栈和权限管理。

4. **加载新进程上下文**：
   - 内核加载新进程的 `task_struct` 中保存的上下文，包括：
     - 恢复寄存器状态。
     - 如果新进程属于不同的地址空间，更新 CR3 寄存器以切换页面表。
     - 设置堆栈指针（ESP）和段寄存器（SS、CS 等）。
   - 如果涉及特权级切换，TSS 提供内核堆栈信息。

5. **执行新进程**：
   - 内核通过 `ret` 或 `iret` 指令跳转到新进程的指令指针（EIP/RIP），开始执行。

### 关键区别

- **硬件任务切换（TSS）**：
  - 完全由 CPU 自动完成，依赖 TSS 存储所有上下文。
  - 开销较大，灵活性低，现代操作系统很少使用。
- **Linux 的软件任务切换**：
  - 由内核代码（`switch_to` 等）手动保存和恢复上下文。
  - TSS 仅用于特权级切换的堆栈管理和 I/O 权限控制。
  - 更高效，适合复杂的调度策略和多核环境。

### 总结

- **TSS 硬件任务切换流程**：通过 GDT 和 TR，CPU 自动保存当前任务状态到 TSS，加载新任务的 TSS 并恢复上下文，完成切换。涉及寄存器、堆栈、CR3 等。
- **Linux 中的 TSS 使用**：Linux 不依赖 TSS 进行任务切换，而是通过软件方式管理上下文。TSS 仅用于特权级切换时的堆栈管理（SS0、ESP0）和 I/O 权限控制。
- **流程差异**：硬件切换由 CPU 自动完成，Linux 使用软件切换以获得更高的灵活性和性能，TSS 仅作为辅助结构。
